# Adaptive Maintenance of a Financial ML Model

Учебно-исследовательский проект по адаптивному обслуживанию (выбору момента и способа обновления) торговой ML-модели.

## Идея проекта

Модель прогнозирует направление будущей доходности акции. На очередном шаге система выбирает операцию обслуживания уже работающей модели:

- `no-op` — оставить текущую модель без изменений;
- `fine-tune` — продолжить обучение текущей модели, добавив новые деревья;
- `retrain` — обучить новую модель с нуля.

Главный объект исследования — не выбор самой акции и не обещание прибыльной торговой стратегии, а выбор операции обслуживания. Экономическая награда (финансовый результат после торговых и вычислительных издержек) должна сравниваться со статистической наградой (например, accuracy или log-loss).

## Текущий статус

Сейчас в `main.ipynb` находится воспроизводимый учебный пилот (маленький проверочный эксперимент):

1. загрузка и проверка данных;
2. построение технических признаков (числовых описаний рынка);
3. построение пятиточечного forward target (будущего ответа модели);
4. обучение LightGBM;
5. реализация `no-op`, `fine-tune` и `retrain`;
6. walk-forward-проверка (движение по времени без использования будущего);
7. приблизительный расчёт портфеля и transaction costs (торговых издержек);
8. метрики, графики и автоматические проверки;
9. заготовка для UCB1 (алгоритма выбора действия по прошлым наградам).

`demo_cycle` — только техническая демонстрация трёх действий по очереди. Он не является обучаемой политикой и не используется как научный результат.

## Данные

### Акции

`Stock_Portfolio_Raw_Adjusted_yfinance.csv` содержит 8 акций основного пула:

```text
AAPL, AMZN, CAT, JNJ, JPM, MSFT, NVDA, XOM
```

Период: `2020-01-02` — `2025-12-31`.

Основные столбцы:

- `Open`, `High`, `Low`, `Close` — дневные цены;
- `Adj Close` — цена закрытия с поправками на дивиденды и сплиты;
- `Dividends` — дивиденды;
- `Stock Splits` — дробления акций;
- `Volume` — объём торгов;
- `Ticker` — тикер.

### Глобальные индикаторы

`Global_Indicators_yfinance.csv` содержит:

- `^GSPC` — индекс S&P 500;
- `^VIX` — индекс ожидаемой волатильности;
- `^TNX` — доходность 10-летних казначейских облигаций.

Они предназначены для глобального контекста (описания общей рыночной ситуации), а не для отдельной торговой позиции.

## Запуск

Используется conda-окружение (изолированная среда Python) `b2t`.

1. Открой проект в VS Code.
2. Открой `main.ipynb`.
3. Выбери kernel (ядро Python) `b2t`.
4. Выполни `Restart Kernel` (перезапуск ядра).
5. Выполни `Run All` (запуск всех ячеек сверху вниз).

Загрузка через `yfinance` по умолчанию выключена: notebook использует локальные CSV. Это делает обычный запуск воспроизводимым и не зависит от состояния внешнего API.

## Важные ограничения текущего пилота

- В пилоте используются три акции для отладки, хотя финальный пул содержит восемь.
- Период пилота ограничен tuning-сегментом (участком для настройки) 2021 года.
- Это не финальный test (финальная оценка); данные 2022–2025 пока не используются для окончательных выводов.
- `compute cost` (стоимость вычислений) пока измеряется временем, но не переведена в денежную reward (награду).
- Комиссии, проскальзывание, налоги и точная модель исполнения требуют отдельной фиксации.
- Использование yfinance имеет ограничения качества и возможный survivorship bias (в выборке могут отсутствовать компании, исчезнувшие с рынка).
- Положительная доходность пилота не доказывает наличие устойчивого торгового преимущества.

## Следующий этап: UCB1

UCB1 должен выбирать действие обслуживания, используя историю:

```text
выбранное действие → полученная net reward (чистая награда)
```

Он не должен получать `probability` LightGBM как свою награду. Вероятность LightGBM используется для торгового сигнала, а reward UCB1 появляется только после завершения соответствующего торгового окна.

Для каждой записи UCB1 понадобятся как минимум:

```text
decision_date
ticker
action
forward_return
transaction_cost
compute_cost
reward
reward_available_at
```

Эти данные следует хранить в отдельном журнале эксперимента, а не добавлять в исходный CSV с рыночными ценами.

Перед подключением UCB1 нужно окончательно определить календарь и delayed reward (отложенную награду): если торговое окно ещё не закончилось, UCB1 не имеет права обновляться его будущим результатом.

## План исследовательского эксперимента

Минимальный core (обязательная часть):

1. `never-retrain`, календарное и drift-triggered baseline (простые методы сравнения);
2. UCB1 без контекста;
3. LinUCB с контекстом (выбор действия с учётом состояния рынка и модели);
4. одинаковые LightGBM, активы, признаки и торговые правила;
5. сравнение economic reward и statistical reward;
6. prequential test (онлайн-оценка, где политика продолжает учиться на новых доступных наградах);
7. пять заранее зафиксированных seed (начальных состояний случайности);
8. paired time-block bootstrap (оценка неопределённости по связанным временным блокам).

Расширения вроде полноценного MDP/FQI, delayed reward с несколькими горизонтами и CCXT должны добавляться только после корректного core.
